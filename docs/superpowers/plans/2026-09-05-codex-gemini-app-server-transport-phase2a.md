# Codex Gemini App Server Transport Phase 2A Implementation Plan

> **For agent 2:** Execute this plan task-by-task in the existing agent 2 chat. Do not create subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the bounded stdio transport, exact-executable observation, stable App Server handshake, and capability-first schema/probe bridge needed by the existing compatibility adapter without touching a provider or user workspace.

**Architecture:** Keep all raw App Server protocol details under `src/app-server`. A dependency-free JSONL client owns framing and request correlation; an exact-process boundary prevents `PATH` fallback; a schema qualifier checks only the stable request subset consumed by the companion; and a handshake driver exposes the two injected functions already expected by `createAppServerCompatibilityAdapter`. Version and SHA-256 remain diagnostics only. Required contract failures remain fail-closed.

**Tech Stack:** Node.js ES modules, built-in `node:test`, built-in streams/crypto/child_process/fs/path, no downloaded dependencies, no live Gemini/9Router call, no user-workspace mutation.

## Protocol decisions locked for this phase

- Use the exact configured absolute executable path; never resolve `codex` from `PATH`.
- Use stdio JSONL with the JSON-RPC `jsonrpc` header omitted.
- Send one `initialize` request with `capabilities.experimentalApi: false`; await its valid response; then send the `initialized` notification.
- Use `model/list` as the only live read-only method probe in this phase.
- Verify `thread/start`, `thread/resume`, `turn/start`, and `turn/interrupt` from the stable JSON schema generated by that exact executable. Do not call those methods as probes because they create or alter state.
- Version or executable-hash changes produce warning/debug evidence but do not block when the required contract passes.
- Malformed framing, handshake, generated schema, required response shape, timeout, or child exit fails closed through the existing `app_server_incompatible` normalization.
- Bound line, stderr, version-output, and request-wait sizes. Do not persist or return raw remote errors, stderr, environment values, or provider data.

  maxLineBytes = 1_048_576,
  onNotification = () => {},

Implementation requirements:

1. Accumulate `Buffer` chunks and split only on byte `0x0a`; remove one trailing `0x0d` before UTF-8 decoding.
2. Reject and close as soon as the unfinished line or completed line exceeds `maxLineBytes`.
3. Accept only non-array objects. Route `{id, method}` to `onServerRequest`, `{method}` to `onNotification`, and `{id, result|error}` to the matching pending request.
4. Reject frames that contain both `result` and `error`, neither field for a response, an unknown response id, a non-string method, or invalid JSON.
5. Remote errors may retain only a scalar remote error code in `details.remoteCode`; never retain raw message/data.
6. Every request has one positive integer id and one timer. A timeout closes the whole client and rejects every pending request.
7. `readable` end/close/error or `writable` error closes the client once. `close()` is idempotent and removes listeners.
8. Catch synchronous and asynchronous callback failures, normalize them to `AppServerProtocolError`, and invoke `onFatal` without allowing an `onFatal` exception to escape.
9. Outgoing messages are bounded by `maxLineBytes`, end with exactly one newline, and omit the `jsonrpc` field.
